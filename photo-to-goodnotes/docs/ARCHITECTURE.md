# Architecture

`preprocessing` prepares photos; the isolated InkSight worker predicts trajectories; `inksight.adapter` converts its native output into `InkDocument`; `strokes` validates and serializes it. `goodnotes` reads a template ZIP, finds a measured genuine pen record, transforms its sampled path and companion geometry, and appends one native record pair per stroke while preserving every other archive member. `rendering` draws the same internal strokes and ingests a human-supplied Goodnotes PDF or screenshot. `evaluation` reports raw and aligned metrics. `optimization` writes small reproducible candidate sets and scores only supplied app exports. `learning` remains reserved for later work.

The central contract is `src/inkbridge/core/models.py`. Modules may depend on it but it has no dependency on vendor formats. Phase 1 now runs InkSight in an isolated Python process and emits an `InkDocument`, JSON, and a blank-canvas vector preview. Actual Goodnotes rendering requires a manual application step until a renderer adapter exists.

The native encoder depends only on the internal stroke models, not InkSight. `encode_strokes` accepts a plain `list[Stroke]`; `encode` accepts an `InkDocument`. The measured vA topology has a fixed sample count inherited from the chosen pen template; input strokes are resampled to that count. Unknown Goodnotes records and fields round-trip unchanged. Unsupported pen layouts raise errors rather than falling back to vector lines. See [roadmap](ROADMAP.md).
