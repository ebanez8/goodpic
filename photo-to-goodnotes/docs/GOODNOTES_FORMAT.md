# Experimental Goodnotes format notes

These are observations from sample files and reverse engineering, **not a guaranteed specification**. A `.goodnotes` file is a ZIP archive with page records under `notes/<UUID>`. Page content records contain field `#7`; a stroke record has field `#2` compressed geometry, field `#4` RGBA color, and pen-related field `#21` in observed examples. Geometry uses Apple-framed LZ4 (`bv41` blocks and `bv4$` terminator). Records are protobuf wire data, often length-delimited.

Vector line geometry and freehand pen geometry are different. Extracted `(x, y, width)` triples describe only part of a pen's path; freehand records may contain additional curve/control points, flags, style templates, and trailing data. Editing only triples while retaining inconsistent companion data can produce distorted renderings. The reported injected letter A imported and remained movable/deletable after reopening, but rendered incorrectly. Partial erasing is unverified.

The encoder preserves unknown ZIP members, protobuf fields, order-sensitive metadata, and template data. Compare controlled native strokes against inserted strokes before interpreting any byte sequence as a stable field. The brief names `t/output/experiment.py` as the baseline, but `t/` is absent in this checkout. The root `goodparse` source and `samples/` informed read-only diagnostics; they remain outside this package.

## Phase 2 measurements (2026-10-30)

The selected source is the first supported genuine freehand pen in `samples/Test4.goodnotes`, page member `notes/F51610D9-2DEC-4842-BD27-12371BC96206`, record index 1. Its content field `#21` is 24. The decompressed `tpl\0` vA blob is 3,798 bytes. A 27-entry uint16 flag run precedes a stored anchor triple and a count of 156 float32 values: 52 `(x, y, radius)` samples. The radius is half the intended ink diameter in canvas units. A 26-entry and a 134-entry uint16 flag run follow. Then a count of 52 precedes 195 float32 `(x, y)` outline pairs. A count of 260 float32 values precedes 52 five-float records `(x, y, radius, tangent_x, tangent_y)`. A final count of 52 precedes 52 uint16 flags. These counts and offsets are checked before writing; a different layout is rejected.

The encoder resamples each internal stroke to the source's 52 points. A single-point dot becomes a sub-0.1 pt microline to avoid a degenerate native path. It maps the secondary outline pairs through the nearest original path segment into the target path's local normal frame. It maps control positions likewise, scales widths, and rotates tangent vectors to the target local direction. An exact affine mode transforms all three coordinate representations for the clone, translation, and scale experiments. This is a deterministic reconstruction hypothesis. The outline's spline semantics, the three flag runs, and some per-record metadata are not fully understood. Real Goodnotes exports are still needed to determine whether the warped outline renders correctly around sharp corners and loops.

The writer copies all unrelated ZIP members byte for byte, retains unknown protobuf wire fields and their order, and changes the cloned record UUID, destination document value, metadata sequence, color, compressed geometry, and length framing. It uses standard `bv41` LZ4 blocks with literal-only compression. `samples/test.goodnotes` supplies the target document; `samples/Test4.goodnotes` supplies the genuine pen topology. No source archive is overwritten. The default canvas-to-page scale `6/11` matches the inspected samples; templates with different canvas mapping need `--canvas-scale`.

The root [goodparse](https://github.com/franzthiemann/goodparse) source was used only for independent read-only diagnostics and parse verification. Its root `LICENSE` is GPL-3.0 despite the root package metadata saying MIT; no source was copied into InkBridge. Confirm licensing before any distribution that combines them.

## Import feedback and v2 correction

The first imported set showed the unchanged Test4 loop (red O) and a central curve from the document template, but generated paths were not visible as intended. Local goodparse output had misleadingly counted both source marks and inserted strokes. The v2 writer clears the target page before appending records. Generated paths now require a near-straight genuine source; the selected Test5 sample has 40 native path samples and an end-to-end distance about 99.8% of its path length. The clone/translation/scale controls use that same source. This removes a loop-to-line nearest-projection ambiguity. It does **not** prove that Goodnotes will render reconstructed paths: the v2 set needs app import and export. If the affine controls render but generated paths do not, the companion outline reconstruction remains wrong. If even the affine controls fail, investigate metadata, bounds, and transforms before further path fitting.

The first v2 import appeared blank in Goodnotes. A comparison with genuine records showed two cross-document mismatches: the cloned metadata and pen content had different field `#1` IDs, although genuine pairs share one ID, and metadata field `#8` retained the source document value. The writer now gives each pair one shared ID and copies field `#8` from the destination page. The six v2 archives were regenerated. Local structural checks pass; their Goodnotes rendering still requires a fresh import.

The next Goodnotes screenshot still showed a blank grid. The writer's `bv41` blocks contained only LZ4 literals, making the compressed block larger than its raw geometry. Genuine files instead use compact LZ4 matches. The writer now emits matching blocks and preserves the source's original compressed bytes for the identity clone. It also clones metadata and content wrappers from a pen on the destination page when one exists. Regenerated files are under both `phase2_experiments_v2` and `phase2_experiments_v3`; import v3 as a new document to avoid viewing an older imported copy. Structural checks pass, but Goodnotes display is still unverified.

Further comparison of genuine records found two per-stroke numeric links: metadata field `#2` equals pen content field `#15`, and the nested value in pen content field `#7` is also unique per stroke. Generated records had reused both values. The writer now creates unique values for each new stroke and keeps the matching pair synchronized. This is based on observed structure; the fields' exact semantics remain unknown.

A fresh `genuine_clone` imported into Goodnotes and displayed the expected green source stroke near the upper middle of the page. This confirms the archive can display copied native ink, but does not validate reconstructed geometry. Inspection of v3 generated geometry found a uint32 outline ring marker (`0, 240` in the selected source pen) was interpreted as an `(x, y)` pair, moving part of the A outline far outside its intended bounds. The writer now preserves that marker; v4 has corrected outline bounds. Goodnotes display of translated and generated paths remains to be checked.

All 13 v4 generated stroke blobs also decompressed with PyArrow's independent `lz4_raw` codec to the same bytes as the local decoder. This rules out a shared error in the local LZ4 encoder and decoder, but still does not prove Goodnotes renders the transformed geometry.

The originally requested `phase2_experiments_v2` files were regenerated after the outline fix. Their translated and A geometry bytes match v4 exactly; only fresh object identifiers and linked tokens differ. Existing copies already imported into Goodnotes must be imported anew to see these bytes.
