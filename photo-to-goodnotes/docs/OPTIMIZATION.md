# Optimization boundary

`EncoderParameters` supplies page-point translations, x/y scale, and stroke-width scale. Curve/control fields are reserved but currently uncalibrated, so candidate generation does not vary them. `candidate-grid` creates nine deterministic candidates with transformed JSON, native archive, PNG/SVG reference, and a manifest. `score-candidate` adds a real supplied Goodnotes rendering, comparison artifacts, metrics, and a lower-is-better score. It accepts `--page`, `--crop`, `--threshold`, `--no-align`, `--weights` (JSON mapping), and `--goodnotes-version`; these settings are saved in the manifest. `rank-candidates` sorts only scored manifests. The default weights are IoU .35, Chamfer .25, pixel difference .15, SSIM .15, and bounding-box error .10. Shape terms use aligned metrics; bounding-box error uses raw positions. Call the objective only after an actual app export exists.

This is a small feedback interface, not automatic correction. A black-box SciPy/CMA-ES loop would require an automated Goodnotes renderer or many manual imports, so it is intentionally deferred. Visual scores cannot prove genuine editable ink. Use the same Goodnotes version and capture settings across candidates and follow the [manual checklist](MANUAL_GOODNOTES_CHECKLIST.md).
